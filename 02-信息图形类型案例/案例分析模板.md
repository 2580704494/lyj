# 案例分析模板

复制为 `案例/CASE-编号-作品名/分析.md` 后填写。

| 字段 | 填写内容 |
|---|---|
| 案例编号与作品名 | 唯一 CASE 编号、原题、中文简称 |
| 作者、日期、出处 | 按原始发布页或作者资料记录，标明日期精度 |
| 图像证据 | 原图或同版页面链接、图面可辨认的区域，以及已核对的内容 |
| 归档方式 | 源链接或已获准公开的本地原图 |
| 主归属与表现形式 | 五种基础类型选一；表现标签可多选，并给证据 |

## A 基本的数据逻辑

写出图在组织的主要关系和最小记录单位。解释为什么把这项关系作为主归属。

## B 统计图形与计算

记录实际使用的图形、指标、单位、分母和已知计算。有数值也要区别图上可读的和能够重新计算的。需要深入讨论字段、统计口径或尺度时，参照 [04 统计图形分析模板](../04-统计图形分析/统计图形分析模板.md)。

## C 视觉编码

指出具体区域的点、线、面、体、符号、色彩分别表达什么。记录最有效的处理和可能的误读。

## D 数据／信息架构

写出建议的表格结构，包括每行代表什么、列有哪些。把图上可见字段和推测字段分开。

## E 视觉叙事架构

记录读图入口、主要阅读方向、关键转折以及辅助信息怎样支撑主线。

## 可以写回说明文档的内容

写一条可迁移的原则或反例、其适用条件和本案证据。在同次提交更新案例索引与相关理论、表现说明。证据不足时，注明具体待核内容。

## 风格迁移记录（涉及克隆或换风格时填写）

记录 style_id/profile_version、完整 bundle 位置、新 task_id、参考来源、不可改变的信息/数据约束、四版提示词位置，以及实际成图和审计记录。把 R 风格规则和 T 任务约束分开核验；未生成或未核验的项目明确标待核。

交接与回查见 [06 仓库联动协议](../06-风格分析与克隆系统/仓库联动协议.md)。新案例仍沿用一份 CASE 主档及既有索引更新规则。
