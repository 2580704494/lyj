## 怎么给一张图分类

在五种基础类型里选一个**主归属**，看的是信息之间的主关系。表现形式可以选多个，帮助查找画法。例如 [PlayStation 演变图](../02-信息图形类型案例/03-时间轴型-Timeline/案例/CASE-001-PlayStation演变/分析.md) 的主归属是「编年型」，表现形式是「时间轴型」。按 A–Z 排列的清单，其主归属可以是「字母表型」。

| 基础类型 | 读者要回答的问题 | 需要核对的关系或字段 |
|---|---|---|
| [编年型](../01-信息图形数据逻辑/01-编年型信息图形概念定义.md) | 事情何时发生，经历了哪些阶段？ | 日期、时间区间或有实际意义的步骤顺序。 |
| [层级型](../01-信息图形数据逻辑/02-层级型信息图形概念定义.md) | 谁属于谁，或处于哪一级？ | 上级 ID、包含关系或明确的等级标准。 |
| [编目型](../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) | 有哪些类别，每一类有哪些对象？ | 对象 ID、类别及可重复执行的分类规则。 |
| [字母表型](../01-信息图形数据逻辑/04-字母表型信息图形概念定义.md) | 知道一个名字，怎样查到它？ | 词条 ID、规范化检索键及排序规则。 |
| [地理图型](../01-信息图形数据逻辑/05-地理图形信息图形概念定义.md) | 对象在哪里，地点怎样相连？ | 点位、区域边界或路线节点。 |

同一个对象可以用不同逻辑组织。例如列出象群迁移的日期，能回答何时经过某地。把节点放到地图上，能看出路线和相对方位。根据作品最主要的问题选择主归属，再另记时间轴型、地标型等表现标签。分类框架和 A–E 的组织方法参考 [Feng 的信息图形知识库](https://github.com/fengbaifan/Infographic-Style-Repository/tree/3e2cae490855b6ddda09b487517bc975e9a9f06b/01-信息图形数据逻辑)，案例判断使用本仓库的案例。

## 新增案例时怎样更新

1. 在 [02 案例索引](../02-信息图形类型案例/README.md) 里查重。按 [案例分析模板](../02-信息图形类型案例/案例分析模板.md) 新建一个案例，记录出处、可核验的图面证据、主归属和表现标签。
2. 在同一次提交里，更新案例索引、对应的表现说明和 [01 理论文档](../01-信息图形数据逻辑/) 的案例链接。一个案例只保留一份主档，其他说明通过链接引用。
3. 新例子如果增加了有效方法、例外或反例，就把变化写进对应文档，并链接证据。只提供了另一张相似的图时，补案例链接即可。说明中区分原图可见内容、对数据结构的推测和设计建议。
4. 图片如已获公开归档授权，放在 02 对应案例目录。外部参考作品可以保留原作链接。01 通过文字链接引用案例。

案例主要来自此前选定的 SCMP 印刷图集和同版公开资料。少数表现形式采用可核验的学术或作者资料，已在案例页标明。具体原则会随新案例或反例补充。
