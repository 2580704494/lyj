# 01 编年型信息图形概念定义

编年型用有意义的先后关系组织信息，让人看懂事情何时发生、怎样演变，或者经过哪些阶段。先后可以来自实际日期，也可以来自必须按顺序完成的步骤。

## A 基本的数据逻辑

最小单位通常是一个事件、一个阶段或一次观测。关键字段是事件 ID 和顺序依据，例如日期、开始与结束时间，或步骤序号。判断时可以试着交换两项的位置。如果调换会破坏事实上的年代或步骤约束，顺序就是信息本身。按名称查找、按销量排名和按材质分组各有自己的排序依据。先后关系本身不能证明因果。

[PlayStation 演变图](../02-信息图形类型案例/03-时间轴型-Timeline/案例/CASE-001-PlayStation演变/分析.md) 以年代为主线，让不同产品和节点沿同一时间参照阅读。

### 怎样判断

先问「我要追踪哪一件事的变化？」用一条主要的时间或阶段序列统领阅读。同一个节点可同时带型号、地区或数值等属性，表格仍可以有多列。出现返工或循环时，用回路线、轮次或日期标明实际过程。

- **与字母表型区分**。日期与前驱关系能解释事情的先后。按首字母重新整理后，读者得到的是名称索引。
- **与层级型区分**。第一步、第二步表达推进顺序。要判断上下位，则需知道谁隶属于谁，或等级依据是什么。
- **与地理图型区分**。同一段行程按日期回答「何时到达」，按地图回答「经过哪里」。看作品把哪一个问题作为主要阅读任务。

## B 统计图形与计算

- 只有事件和顺序时，用节点时间轴或阶段示意即可。日期可以是年、月或日，精度按资料保留。
- 要表达到下一事件隔多久，可计算相邻时间差；要表现阶段持续多久，用结束时间减开始时间，再用区间条呈现。
- 同一指标连续观测时，可用折线图看趋势；事件集中程度可按期计数。区分本期数与累计数，有缺测时标明空缺。

## C 视觉编码

| 元素 | 用法 |
|---|---|
| 点与线 | 点标出事件。线引导顺序；只有在真实时间尺度一致时，线段间距才代表时长。 |
| 面与体 | 面区分阶段、时代或持续区间。立体对象可辅助识别产品，体积默认不承担数值。 |
| 符号与色彩 | 图标帮助识别事件类型。同类在不同时间段用同一颜色，突出少数关键转折并给图例。 |

## D 数据／信息架构

建议先建事件表，一行记一件事。列可设为 `event_id`、`事件名称`、`日期或阶段序号`、`时间精度`、`类别`、`说明`、`来源`。有区间时加起止字段，有多条并行线时加轨道字段。原始日期与显示用文字分开记录。案例只标了年份时，无须补出月份或日期。

下面是字段结构示例，内容为虚构阶段。

| 事件 ID | 阶段序号 | 阶段名称 | 前置阶段 ID |
|---|---:|---|---|
| E01 | 1 | 记录现状 | 无 |
| E02 | 2 | 整理记录 | E01 |
| E03 | 3 | 绘制草图 | E02 |

只有确有依赖时才填前置阶段。两个独立事件发生在同一天时，可以在同一时间刻度分轨显示。相对时间和真实日期都可记录，出图前应说明横轴采用哪一种。

## E 视觉叙事架构

先交代起点和时间范围，再沿主轴介绍关键节点，最后把读者带到后续变化或当前状态。先画主时间线，再安排插画和旁注。等距只表示顺序的版面，应写明「节点等距排列」。[时间轴型说明](../02-信息图形类型案例/03-时间轴型-Timeline/00-标签说明.md) 提供具体表现方法。

读 PlayStation 案例时，可以先顺年代辨认产品演变的主线，再进入某一年阅读型号注释。这个案例能说明事件如何排列。需要比较相隔多久时，应按标注的年份计算时间差。
