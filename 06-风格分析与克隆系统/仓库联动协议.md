# 仓库联动协议 1.0

本协议把 01–05 的方法结论交给 SC-IMG 的任务层，保留风格层独立。由人或当前大模型读文档、查看资料、填写结论；离线工具负责结构映射与检查，不自动理解图片或章节。

## 模块如何选择

| 模块 | 进入条件 | 必读入口 | 交给 06 | 输出后回查 |
|---|---|---|---|---|
| 01 | 存在信息关系 | [数据逻辑](../01-信息图形数据逻辑/README.md) 及所选类型 | 主关系、字段、顺序/归属/地理锁定项 | 关系是否改变 |
| 02 | 分析或设计信息图 | [类型索引](../02-信息图形类型案例/README.md)、适用标签/案例 | 表现形式、CASE 引用、阅读目标 | 是否仍回答同一问题 |
| 04 | 数值、比例、尺度或统计结论 | [统计模板](../04-统计图形分析/统计图形分析模板.md) | 数据来源、单位、口径、尺度、缺测规则 | 复算及编码核对 |
| 03 | 用重复图符表示数量 | [视觉编码](../03-ISOTYPE信息图/02-图符语言与视觉编码/图符语言与视觉编码.md) | 每符单位、图符数、等大规则、余数处理 | 数量×单位与原值一致 |
| 05 | 信息分组、路径、标注或前景可能受风格影响 | [规则索引](../05-Gestalt视觉组织原则/README.md) 及相关 G 规则 | 归属、对齐、连接、图底与可读性约束 | 有无误分组和遮挡 |
| 06 | 提取、应用、迁移或复查风格 | [系统入口](./START_HERE.txt) | profile + task + 四版输出 | 核心与任务分别查 |

顺序按依赖确定：数值先复算，再定图符单位；视觉组织先提出要求，出图后再检验。纯插画可仅走 06，按需要参考 05。不要以流程完整为由引入无关统计约束。

## 文件与字段交接

使用 [空白交接表](./templates/repo_handoff.json)，结构见 [handoff schema](./schemas/repo_handoff.schema.json)，已填示例见 [repo_handoff.json](./examples/repo_handoff.json)。

| handoff 字段 | 内容 | 映射 |
|---|---|---|
| `handoff_version` | 固定 `1.0` | 独立于 bundle schema 版本 |
| `task` | 新任务的 id/mode/content/context/requirements/unresolved | **完整替换旧 task**，防止旧主题锁定项残留 |
| `modules` | 唯一模块编号、仓库相对文档路径、使用原因 | 记入 trace，不写入 profile |
| `constraints` | 每项含唯一 T ID、module、source、must 优先级、中英 instruction/check、conflicts_with | 追加到新 task.requirements |
| `unresolved` | 来源或业务判断未解决项 | 追加到 task.unresolved，阻止正常 ready 编译 |

task 内已有的 requirements 用于新主题自己的要求；不要复制旧主题内容。旧任务需要保留的要求须明确复制到交接表。风格 profile 内容完全保留，包括状态与验证记录；新任务的成图结果仍需另外验证，不能借旧记录宣称通过。

执行 `python tools/repo_adapter.py handoff.json style_bundle.json --out work/new_task`，得到 `bundle.json`、`handoff.json`、`trace.json`。trace 记录输入/输出摘要、源风格 ID/版本和每项来源；重新运行使用新目录。它不是视觉评审证明。

`modules[].source` 和 `constraints[].source` 为实际仓库相对文档路径，必须与模块目录一致；适配器在完整仓库中检查文件存在，拒绝绝对路径与越界。单独下载 06 时，信息图联动需要补齐相关仓库章节。

## 冲突和失效处理

1. 已知某任务约束与风格 R 规则不兼容时，将 R ID 放入该 T 项 `conflicts_with`。当前条件下生效的冲突阻止合并和正式编译；未知规则 ID 同样拒绝。
2. 数据、单位、真实关系不能因装饰风格改写；风格核心也不能被静默删除。选择兼容风格、调整不影响事实的布局，或明确创建派生风格。不存在同时满足方案时说明不可兼容。
3. 未写进字段的语义冲突无法由工具自动发现。人/模型须逐条对读：例如“装饰性大小变化”可能与“等大计数图符”冲突；“高密度背景”可能使标注失读。
4. 标为 unresolved 的缺项允许交接草稿，后续仅可 `--draft` 导出。数据未知不能填写零，来源失效不能写已核验。
5. 风格用于图符内部时保持计数轮廓、等大关系和图例可辨认。面积/长度编码不能因透视或阴影产生错误比较。

## 双向写回

一次完成的案例保留一个 CASE 主档。02 记录原作与表现形式，04 保留计算，03 保留计数设计，05 保留组织分析，06 保留风格档案与测试记录，彼此链接。新增案例按 [已有同步规则](../04-统计图形分析/README.md#新增案例时怎样更新) 更新索引。

分析样例不能自动升级成整类风格定律；只有相应证据支持时才修订理论/规则页。参考原作与本次生成作品分别记录，避免来源混淆。

## 三种启动方式的联动边界

- **仓库**：统一入口能找到所有章节；按需要实际加载，不把能访问等同已读完。
- **网页文件**：WEB_START 包含完整风格规范。要做信息图联动，再上传本协议、交接表和用到的章节；不能仅凭单文件声称看过仓库案例。
- **记忆**：保存仓库入口和完整档案位置，恢复时重新获取。只有摘要就报告 memory_only，不能省去规则/证据加载。
