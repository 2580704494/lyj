# 完整联动示例：把风格用于图符计数

本例使用自拟数据 A=30、B=50，每个纸杯图符代表 10 个纸杯，结果为 A 行 3 个、B 行 5 个。风格采用已有自拟剪纸测试档案。全部用于软件演示，不是从真实参考图提取的风格，也没有实际成图通过记录。

## 1. 明确输入

- 风格：[demo_bundle.json](./examples/demo_bundle.json)，其旧任务为狐狸；本例必须替换旧 task。
- 新任务与上游约束：[repo_handoff.json](./examples/repo_handoff.json)。其中记录 01–05 的来源、用途、五条中英 must 约束和核对方法。
- 01 明确 A/B 两组；02 选两行比较；04 核对 30/10=3、50/10=5；03 锁定同类等大图符；05 检查行间分组和标签归属。

这些数值是本示例自行设定；来源章节提供方法，不为自拟数值提供真实调查证据。

## 2. 合并新任务

在本模块目录运行，输出目录须新建或为空：

```text
python tools/repo_adapter.py examples/repo_handoff.json examples/demo_bundle.json --out work/isotype
```

检查输出 `bundle.json`：profile 与原档案完全相同，task 改为纸杯比较，旧的 T001 狐狸约束消失，新增 TREPO001–TREPO005。`trace.json` 记录源摘要与来源映射。

## 3. 检查并导出

```text
python tools/scimg.py check work/isotype/bundle.json
python tools/scimg.py compile work/isotype/bundle.json --out work/isotype_exports --draft
```

自拟档案保持 illustrative/draft，检查会列出待核项，不能用于正式风格验证。检查四版都包含五条任务约束，中文英文数量一致，不再出现狐狸；风格核心依然是分层平面色块、硬边和明度层级。

## 4. 发现冲突怎么办

若参考风格核心确实要求通过不同大小的图符表达画面节奏，它可能与本例的等大计数要求不兼容。查看相应 R 规则后，在等大约束的 `conflicts_with` 填入实际 R ID。当前生效的显式冲突会阻止合并；工具不会从自然语言自动推断这种冲突。

可改用兼容风格、把装饰节奏放到不承担数值编码的背景，或另建明确说明差异的派生风格。不能为了相似将 3 个杯子放大成 5 个的视觉重量，或删掉等大要求。

## 5. 实际成图后怎样验收

拿到图后数 A 行是否恰好 3 个、B 行是否恰好 5 个，检查同类图符等大、图例=10、标签与分组正确，再检查 R 风格规则。按 review schema 记录每条 R/T 的真实观察。任何 must 未满足，就记录问题并修订，不能仅凭示例命令运行成功写成成图通过。

## 6. 换主题复用

将纸杯换成回收电池时，保留 profile；重新填写 handoff.task，并在约束中同步更换对象与新数据。每符单位、图符数、类别标签重新计算，不能只替换一个名词后沿用旧数值。信息图之外的纯视觉主题可跳过图符约束，但仍重新检查本次适用条件。
